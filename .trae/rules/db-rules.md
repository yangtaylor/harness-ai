# 数据库设计/脚本/版本回退规范

## 命名规范
- 表名/字段名: 小写下划线 `user_order`
- 必须包含字段: `id`, `create_time`, `update_time`, `is_deleted`

## SQL规范
- 禁止 `SELECT *`
- 禁止 WHERE 子句对字段做函数运算
- 加解密在应用层完成，禁止在 SQL 中执行

## 版本管理
- 变更脚本命名: `update_db_{版本号}.sql`
- 回退脚本命名: `rollback_db_{版本号}.sql`

## 变更影响分析规范
每次数据库变更前，必须编写 `impact-analysis.md`：

### 必须分析的内容
1. **变更类型**: 新增表 / 修改表结构 / 删除表 / 新增字段 / 修改字段 / 删除字段 / 索引变更
2. **影响范围**:
   - 受影响的 API 接口列表
   - 受影响的前端页面列表
   - 受影响的定时任务/批处理
   - 受影响的报表/统计逻辑
3. **数据迁移方案**:
   - 是否需要数据迁移脚本
   - 迁移期间是否影响线上服务
   - 迁移回滚方案
4. **兼容性分析**:
   - 是否向后兼容
   - 旧版本代码是否仍能正常运行
   - 是否需要同步发布前端/后端
5. **风险评估**:
   - 数据丢失风险
   - 性能影响风险
   - 线上故障风险

### 影响分析输出位置
`3db/{版本号}/impact-analysis.md`
